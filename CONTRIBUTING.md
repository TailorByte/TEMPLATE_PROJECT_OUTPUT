## How Can I Contribute?

There are many ways to contribute, from writing tutorials or blog posts, improving the documentation, submitting bug reports and feature requests or writing code which can be incorporated into `TEMPLATE_PROJECT_OUTPUT` itself.

### Reporting Bugs

*   **Ensure the bug was not already reported** by searching on GitHub under [Issues](https://github.com/your-org/your-repo/issues). <!-- TODO: Replace with actual link -->
*   If you're unable to find an open issue addressing the problem, [open a new one](https://github.com/your-org/your-repo/issues/new). Be sure to include a **title and clear description**, as much relevant information as possible, and a **code sample** or an **executable test case** demonstrating the expected behavior that is not occurring.
*   Describe the **exact steps which reproduce the problem** in as many details as possible. For example, start by explaining how you started the project, or an example of the command used.
*   Explain which **behavior you expected to see** and **what you saw instead**.

### Suggesting Enhancements

*   Open a new issue.
*   Clearly describe the enhancement you are proposing.
*   Explain why this enhancement would be useful to other users and project maintainers.
*   Provide code examples if possible to illustrate the new functionality.

### Pull Requests

*   Fork the repository and create your branch from `main` (or the current development branch).
*   If you've added code that should be tested, add tests.
*   If you've changed APIs, update the documentation.
*   Ensure the test suite passes.
*   Make sure your code lints.
*   Issue that pull request!

## Styleguides

### Git Commit Messages

*   Use the present tense ("Add feature" not "Added feature").
*   Use the imperative mood ("Move cursor to..." not "Moves cursor to...").
*   Limit the first line to 72 characters or less.
*   Reference issues and pull requests liberally after the first line.
*   Consider using [conventional commits](https://www.conventionalcommits.org/) for more structured commit history.

### Code Styleguide

*   Follow the coding style of the language/framework being used (e.g., PEP 8 for Python, Prettier for JavaScript/React).
*   Use linters and formatters as configured in the project (e.g., Flake8, Black, ESLint, Prettier).
